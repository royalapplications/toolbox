Starts one Azure VM if needed, resolves its current IP address, and generates selected RDP, password-based SSH, and Azure AD-based AzSSH connections.

## Microsoft Azure VM Dynamic Folder

**Version:** 1.0.0  
**Author:** Ghost93

This sample generates connection objects for one Azure virtual machine. Duplicate the imported Dynamic Folder for additional VMs and change only its Custom Properties. The wrapper embeds a PowerShell 7 script inline; when the Dynamic Folder reloads, the wrapper writes it to a temporary file, invokes it with `pwsh.exe`, then deletes the temporary file.

Azure AD SSH uses the Windows Custom Terminal PTY support requested in [toolbox issue #141](https://github.com/royalapplications/toolbox/issues/141).

### Prerequisites

- Windows and Royal TS 26 or newer.
- PowerShell 7 with the Az module: `Install-Module Az -Scope CurrentUser`.
- A cached PowerShell Azure session created with `Connect-AzAccount`.
- For AzSSH, Azure CLI with SSH extension 2.0.4 or newer and a cached `az login` session.
- The wrapper starts the embedded worker with PowerShell `-ExecutionPolicy Bypass` for that child process. This does not elevate privileges; review the behavior against local PowerShell execution policy requirements.
- The PowerShell identity must be allowed to read the VM, its instance state, network interface, and public IP. If **StartVm** is `true`, it also needs permission to start the VM. Grant only the required permissions.
- For AzSSH, configure the Linux VM with the Entra SSH login extension and a managed identity. Assign the Azure CLI identity either **Virtual Machine User Login** or **Virtual Machine Administrator Login** on the VM or its resource group.
- Royal TS credentials matching **CredentialName** for RDP and **SshCredentialName** for password-based SSH.

### Setup

- Import this `.rdfx` into Royal TS. The PowerShell 7 script that queries Azure is embedded inside the wrapper; no additional file needs to be downloaded.
- Set **SubscriptionId** to a GUID, then set **ResourceGroup**, **VmName**, **ConnectionName**, credential names, **IpType**, and **Protocols**.
- **Protocols** accepts `RDP`, `SSH`, `AzSSH`, or comma-separated combinations such as `RDP,SSH,AzSSH`.
- Optional: set **StartVm** to `true` to auto-start a stopped VM when the Dynamic Folder reloads. Default is `false`; if the VM is stopped, the reload fails with a visible error rather than silently starting the VM and incurring Azure cost.
- Optional: set **EnableFileLogging** to `true` while troubleshooting to write a diagnostic log. File logging is disabled by default. When enabled, the worker appends timestamps, resource names, IP addresses, and Azure error details to `%LOCALAPPDATA%\RoyalTS\AzureVmDynamicFolder\logs\Get-AzureVmConnections.log`. The log has no automatic rotation or retention cleanup; review or delete it according to local policy.
- Reload the Dynamic Folder.

### Behavior

- When **StartVm** is `true`, the script starts a stopped VM, waits for provisioning and network readiness, then emits deterministic RoyalJSON connection IDs. When **StartVm** is `false` and the VM is stopped, the reload fails; start the VM manually or set **StartVm** to `true`.
- RDP and SSH reference Royal TS credentials by name. No password or private key is emitted.
- AzSSH starts an embedded Custom Terminal and runs `az ssh vm` with a forced TTY and Bash login shell. When **StartVm** is `true`, the generated command also runs `az vm start` each time the AzSSH connection opens. This can add connection delay and Azure activity, and the Azure CLI identity must have permission to start the VM. Azure CLI performs the Azure AD authentication.
- Public RDP or SSH requires the VM's network security group to permit the selected port from the Royal TS client.
- Diagnostics are written to `%LOCALAPPDATA%\RoyalTS\AzureVmDynamicFolder\logs\Get-AzureVmConnections.log` with a cross-process lock.
